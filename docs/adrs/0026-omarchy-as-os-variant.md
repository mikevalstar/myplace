# ADR-0026: Omarchy as an OS variant, not a profile

## Context

A personal desktop now runs [Omarchy](https://omarchy.org/) (Arch + Hyprland, `ID=omarchy`, `ID_LIKE=arch` in `/etc/os-release`). It is a `personal-linux` desktop in every sense [ADR-0017](0017-linux-desktop-profile.md) cares about — it wants the SSH host list, the fonts, the desktop tooling — but Omarchy is an *opinionated* distro that owns and re-edits a layer of `$HOME` config that the fleet setup also manages:

1. **Theming is generated.** Terminal (alacritty/ghostty/kitty), neovim, btop, bat, starship and Claude Code configs import from `~/.local/state/omarchy/current/theme/`; `omarchy theme set` and `omarchy font set` rewrite them with sed. Our hardcoded Catppuccin + FiraCode terminal configs would break theme switching and show drift after every font change.
2. **Neovim is packaged.** `omarchy-nvim` ships a LazyVim tree whose `lua/plugins/theme.lua` is a symlink to the current theme, repaired by shipped migrations. Our `~/.config/nvim` would replace it and fight every migration. The distro's nvim (0.12.x) is current, so our `/usr/local` static build would only shadow it.
3. **mise is shared, and Omarchy writes to the global config on every tool run.** Omarchy's agent/tool launchers (`~/.local/bin/claude`, `codex`, `gh`, `opencode`, `hunk`, …) are wrappers generated by `omarchy-mise-install` that run `mise use -g <tool>` and then exec it. `mise use -g` writes into `~/.config/mise/config.toml` — the exact file our baseline manages. Managing it on Omarchy means perpetual drift: every wrapper run re-adds an entry, every `myplace update` strips it out. Migrations also assume they can edit that file (one uninstalls any mise `herdr` so it can't shadow the packaged one).
4. **bash is the shell layer.** Omarchy's aliases, functions and env (`EDITOR=omarchy-launch-editor --inline`, `BAT_THEME=ansi`, `MANPAGER`, locale fixups) live under `/usr/share/omarchy/default/bash/`. zsh works fine on Omarchy (`OMARCHY_PATH` reaches it via `/etc/profile.d/omarchy.sh` and the uwsm session env); you just don't get that layer for free.
5. **System updates are Omarchy's.** `omarchy update` runs migrations, keyring updates, `mise up`, firmware — a bare `pacman -Syu` from anywhere else is unsupported. The `outdated` inventory has a shelly source (CachyOS-only) but nothing for a plain pacman box.

None of this makes Omarchy a different *kind* of machine. It's a desktop (profile axis) on Linux (OS axis) with a distro-owned desktop layer. The fix is gating, not new machinery.

## Options considered

### Option A — A new `omarchy` profile

Add a fifth profile and gate everything on it. Rejected: profile is the *desktop vs server* axis (ADR-0017) — what a machine is *for*. Omarchy is *which Linux* it runs, and a profile would either duplicate `personal-linux`'s gates everywhere or make the two drift apart. It would also conflate the answer to "does this box get the SSH hosts?" with "does this box own its terminal theme?".

### Option B — Make the managed configs Omarchy-aware

Keep managing terminal/nvim/starship configs but template them to import Omarchy's theme file and drop the colour blocks. Rejected: more template branches, and it still fights `omarchy font set`, which rewrites the file in place. Omarchy's versions of these files are the better ones on Omarchy.

### Option C — Gate on the OS-release id; Omarchy owns the desktop layer (chosen)

Treat Omarchy as an **OS variant**, the same axis as darwin vs linux: templates read `.chezmoi.osRelease.id` (`dig "osRelease" "id" "" .chezmoi` so macOS, which has no os-release, evaluates cleanly). No new profile; the machine is `personal-linux`. Split ownership:

- **Omarchy owns the desktop layer:** terminal configs, neovim, starship, bat, fonts (`omarchy font set`), and `~/.config/mise/config.toml`.
- **myplace owns everything portable:** shell (zsh + oh-my-zsh, `.zshrc`, `.mvdotfiles.zsh`), secrets, `~/.mvscripts`, git config, herdr config and plugins, and the mise CLI baseline.

## Decision

Option C. Concretely:

1. **Detection** is `.chezmoi.osRelease.id == "omarchy"` in templates and `[ -d /usr/share/omarchy ]` (the `OMARCHY_PATH` root) at shell runtime. The profile stays `personal-linux`.
2. **Ignore what Omarchy owns** via `.chezmoiignore` entries gated on that id: `.config/alacritty/**`, `.config/ghostty/**`, `.config/nvim/**`, `.config/starship/**`, `.config/bat/config`, and `.config/mise/config.toml`. The source tree is unchanged for every other machine. herdr's `config.toml` is deliberately **not** ignored — ours (with the command-palette binding) wins, and Omarchy's seeded one is backed up by hand before the first apply.
3. **mise baseline goes to `conf.d` on Omarchy.** The tool set lives once, in `.chezmoitemplates/mise-config.toml`; `dot_config/mise/config.toml.tmpl` renders it everywhere else, and `dot_config/mise/conf.d/myplace.toml.tmpl` renders it on Omarchy (each file is ignored on the other kind of machine). mise merges `conf.d/*.toml` with `config.toml`, and `mise use -g` only ever writes `config.toml` (verified with `mise config ls` / `mise use --dry-run` under an isolated `XDG_CONFIG_HOME`). So Omarchy's wrappers scribble on their file, ours stays clean, and the fleet baseline reaches the box unchanged — including anything added later. `config.toml` loads last, so an explicit Omarchy pin beats our `latest` on a conflict. `herdr` is gated out of the baseline on Omarchy (a migration uninstalls a mise herdr so it can't shadow `/usr/bin/herdr`). Node stays fnm's (ADR-0007); Omarchy's `dev-env` installer is simply not run.
4. **zsh everywhere; Omarchy's shell layer is sourced, not copied.** `.zshrc` sources Omarchy's `env-bootstrap` + `envs` (POSIX) when the Omarchy root exists, so `EDITOR`/`BROWSER`/`BAT_THEME`/`MANPAGER`/locale match the distro — and our own `EDITOR=nvim` export yields to it there. `.mvdotfiles.zsh` sources Omarchy's `aliases` and the zsh-clean `fns/*` inside the interactive-only block (so agent shells stay clean), **before** our aliases so ours win on a name clash (`c`, `ls`, `lt`), and drops Omarchy's `cd=zd` alias because zoxide's `--cmd cd` already owns `cd`. The `tmux`, `herdr` and `drives` fns are skipped: they rely on bash's 0-indexed arrays and `read -p`, which misbehave in zsh. Bash-only pieces (`inputrc`, `completions`, `shell`, `init`) are not sourced. Sourcing means the layer tracks `omarchy update` instead of drifting in a copy. `chsh -s /usr/bin/zsh` stays a one-time manual step (provision never prompts for a password).
5. **Provision script on Arch:** `pm_install` maps `build-essential` → `base-devel` and uses `omarchy pkg add` when present (it wraps `pacman -S --needed` with a post-install check); rustup comes from the `rustup` package on pacman systems (then `rustup default stable`, since the package ships no toolchain) instead of the curl installer; the neovim static build is skipped whenever a distro nvim ≥ 0.10 that isn't ours is already on PATH — so Omarchy's packaged nvim is left alone and nothing nvim-related runs there. sudo prompts during an interactive bootstrap/update are accepted on password-sudo desktops (same as every other such machine).
6. **`outdated` gains a `pacman` source**, present-if-installed like brew/shelly: `checkupdates` (pacman-contrib; read-only, syncs a *temporary* database) for the repos and `yay -Qua` for the AUR (prefixed `aur:`). It never runs `pacman -Syu` — `omarchy update` owns that. On a CachyOS box that has both shelly and checkupdates the two sources overlap; accepted (both read-only).
7. **`sysinfo` runs `fastfetch --config none --format json`.** Omarchy ships an `/etc/fastfetch/config.jsonc` whose module list has no `OS` or `LocalIp` entries, so plain `--format json` inherited it and reported an empty OS. Pinning the config makes the module set ours on every machine, which it should have been from the start (ADR-0013's option is unchanged; this is the invocation).

## Consequences

**Easier**

- One profile fewer to reason about; every ADR-0017 gate keeps meaning "desktop".
- Omarchy's theme switching, font switching, nvim migrations and mise wrappers all keep working; `myplace status` is clean after using them.
- New fleet tools land on Omarchy through the same one-line template edit as everywhere else.
- Any pacman/Arch box (not just Omarchy) now shows repo + AUR updates in `outdated`.

**Harder / committed to**

- Two files render the mise baseline; `.chezmoitemplates/mise-config.toml` is the single place to edit (the guide says so). `internal/mise.Trust` still trusts `config.toml` only — the global `conf.d` is auto-trusted by mise, so no code change, but it's a thing to know.
- Omarchy machines don't get our terminal/nvim/starship/bat look. That's the point, but a keymap you add to `dot_config/nvim` won't reach them.
- The shell-layer sourcing is runtime-gated on `/usr/share/omarchy` rather than templated, so `.zshrc`/`.mvdotfiles.zsh` stay plain files; the trade is a few lines that no-op everywhere else.
- If Omarchy's `dev-env` installer is ever run, its `mise use -g node` lands in *their* `config.toml`, and mise's node shadows fnm's under our zsh. Not a conflict, just two Nodes; don't run it.
- The `hdl`/`tdl` dev-layout fns stay bash-only (`bash -ic hdl …` if wanted). Revisit if Omarchy ports them.
